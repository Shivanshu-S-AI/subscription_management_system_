1. AUTHENTICATION & LOGIN SYSTEM
================================================================================

1.1 Architecture & Role-Based Access Control (RBAC)
---------------------------------------------------
- Modular monolith user authentication powered by Supabase Auth with server-side cookie sessions (SSR) using `@supabase/ssr`.
- Three strictly partitioned user roles defined in `public.user_role` database enum:
  * 'admin': Unrestricted administrative authority over catalog, plans, rules, team, and billing.
  * 'staff': Operational handling of customers, quotes, subscriptions, invoices, and payments.
  * 'customer': Self-service access strictly isolated to their own subscriptions and invoices.
- Database trigger `handle_new_user()` automatically executes on `auth.users` insert, creating a row in `public.profiles` defaulting to the 'customer' role to eliminate unauthorized privilege escalation.

1.2 Public Customer Authentication & Registration Flow
------------------------------------------------------
- Route: /signup
  * Captures Customer Full Name, Email Address, and Password.
  * Real-time client-side password policy validator and server-side verification before auth account creation.
  * Automatically provisions customer profile in `public.profiles` linked to Supabase user ID.
  * Dispatches confirmation and redirects customer to portal onboarding.
- Route: /login
  * Dedicated sign-in for external business customers.
  * Validates credentials and verifies user role in `public.profiles`.
  * Redirects legitimate customers directly to /portal.
  * Strictly blocks staff or admin accounts attempting customer login, rerouting them to /internal-login.

1.3 Internal Staff & Admin Unified Login Flow
---------------------------------------------
- Route: /internal-login
  * Single, unified authentication page featuring an interactive tabbed card:
    - [Admin Tab]: Designed for business owners and system administrators.
    - [Internal Staff Tab]: Designed for operational team members.
  * Smart Identifier Recognition:
    - Supports login using full email addresses or shorthand system usernames.
    - Admin shorthand accounts recognized:
      1. 'shivanshu' / 'shivanshu@brightloopsoftware.com' (Admin: Shivanshu)
      2. 'aryan' / 'aryan@brightloopsoftware.com' (Admin: Aryan)
      3. 'hiren' / 'hirensir' / 'hiren@brightloopsoftware.com' (Admin: Hiren Sir)
      4. 'admin' / 'admin@brightloopsoftware.com' (Default System Administrator)
    - Staff shorthand accounts recognized:
      1. 'staff' / 'staff@brightloopsoftware.com'
      2. 'alex.ops' / 'alex.ops@brightloopsoftware.com'
      3. 'james.ops' / 'james.ops@brightloopsoftware.com'
  * Automatic Cross-Tab Role Destination Routing:
    - If an administrator signs in via the Staff tab, the system recognizes their role and directs them to /admin.
    - If a staff member signs in via the Admin tab, the system enforces boundaries and routes them to /staff.
  * UI Navbar Entry Point:
    - The public navigation bar features a distinct "Staff Login" button linking directly to /internal-login.

1.4 Password Security & Strength Engine
---------------------------------------
- Implemented in `src/modules/auth/validation.ts`.
- Enforces enterprise credential criteria:
  * Minimum length > 8 characters.
  * At least one uppercase character (A-Z).
  * At least one lowercase character (a-z).
  * At least one special symbol (!@#$%^&*()_+-=[]{}|;:,.<>?).
- Password validation component provides live visual cues (checkmark / cross) on active input.

1.5 Password Recovery & Reset Flow
----------------------------------
- Route: /forgot-password
  * Accepts registered user email address.
  * Generates and transmits secure password reset token via email.
  * Displays confirmation card with instructions to check inbox.
- Route: /reset-password
  * Validates token payload from URL hash / session.
  * Enforces standard password strength rules on new password entry.
  * Updates Supabase Auth credentials and confirms success with direct login link.

1.6 Session Management & Route Protection Middleware
----------------------------------------------------
- Handled at Next.js edge runtime via `src/middleware.ts` and `src/lib/supabase/middleware.ts`.
- Route Boundary Matrix:
  * /admin/*   -> Allowed: 'admin' only. Blocked: Redirects to /internal-login.
  * /staff/*   -> Allowed: 'admin', 'staff'. Blocked: Redirects to /internal-login.
  * /portal/*  -> Allowed: 'customer' only. Blocked: Redirects to /login.
  * Public (/, /login, /signup, /internal-login, /forgot-password) -> Accessible to all.

2.9 Recurring Billing Engine & Automated Batch Processor
--------------------------------------------------------
- Route: /admin/billing
- Functions:
  * Centralized billing engine executing scheduled recurring subscription charges.
  * Automated Detection: Scans all subscriptions in 'active' status where `next_billing_date <= today`.
  * Invoice Generation:
    - Generates new confirmed tax invoice for each eligible subscription.
    - Advances subscription `next_billing_date` forward by cadence interval (e.g., +1 month).
  * Critical Duplicate Prevention & Idempotency:
    - Detects whether an invoice has already been generated for the current billing window.
    - Executing billing multiple times on the same date creates 0 duplicate invoices.
  * Auto-Close Expiration Handler:
    - Automatically closes expired subscriptions if `auto_close = true` and `expiry_date <= today`.
  * Real-time Execution Dashboard:
    - Summarizes processed contracts, invoices created, duplicates prevented, and contracts closed.

4. CUSTOMER PORTAL (/portal)
================================================================================

4.1 Security Isolation & Multi-Tenant Data Boundaries
-----------------------------------------------------
- Built with strict data isolation principles:
  * Every server action, API query, and data fetch filters records strictly by `auth.uid()`.
  * In the data layer: `getCustomerSubscriptionById(customerId, subscriptionId)` and
    `getCustomerInvoiceById(customerId, invoiceId)` return `null` if the record is owned by
    another customer, resulting in an immediate 404 Not Found.
  * Customer A modifying URLs or parameters can NEVER access Customer B's data.
  * PostgreSQL Row Level Security (RLS) policies enforce this isolation at the database layer.

4.4 Self-Service Lifecycle Operations (Governed by Plan Policies)
-----------------------------------------------------------------
- Customers can independently perform lifecycle operations subject to Admin-defined policies:
  * Pause Subscription:
    - If `pause_eligible = true` in the subscription plan, customer can click "Pause Subscription".
    - Immediately freezes subscription status to 'paused'.
    - If `pause_eligible = false`, the action is hidden and blocked server-side with an error message.
  * Resume Subscription:
    - Allows customer to un-pause a paused subscription back to 'active' status.
  * Early Renewal:
    - If `renewal_eligible = true`, customer can initiate self-service renewal.
    - Automatically advances `next_billing_date` and extends contract term.
